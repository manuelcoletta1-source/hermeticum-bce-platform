The problem (real world)

Robotics and autonomy increasingly operate in shared physical environments. Without a deterministic identity boundary, the system relies on informal attribution and post-facto logs. That becomes fragile under safety, procurement, and incident response constraints.

Attribution

Who operated the system? Under which scope? With which policy? Post-facto answers are not enough.

Safety

Autonomy needs hard gates. Identity must be established before action, not after incidents.

Audit

Regulated deployments need deterministic verification and append-only evidence, not editable logs.

The core claim: identity is an execution dependency. If identity cannot be verified deterministically, the system should not operate.

The execution rule

Minimal, deterministic, enforceable at the operational boundary:

identity_valid == true ? EXECUTE : BLOCK
failure_mode = FAIL_CLOSED
evidence_mode = APPEND_ONLY
public_surface = HASH_ONLY
