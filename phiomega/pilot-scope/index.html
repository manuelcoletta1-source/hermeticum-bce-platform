Industrial Pilot Scope (Statement of Work)

This document defines the practical scope of a 30-day ΦΩ pilot: verifiable machine identity, append-only evidence logging, deterministic verification, and a final technical report.

Back to ΦΩ Pilot Deliverables Requirements

1) Objective

Validate ΦΩ on a real industrial system (robot / PLC / cell) in read-only mode, producing a verifiable identity and an evidence trail of operational events. The pilot is designed to be fast, minimally invasive, and aligned with EU auditability principles (hash-only, append-only, fail-closed).

2) Pilot mode: Laptop Mode (read-only)

  • Deployment: ΦΩ runs on a laptop connected to the machine network or log export source.
  • Access level: read-only (log ingestion, no machine control).
  • Inputs: file export (CSV/JSON), syslog, gateway feed (HTTP), or industrial protocols in read mode.
  • Outputs: chained evidence log, deterministic verification, and a final report.

3) Deliverables

D1 — Machine Identity Pack (MIP)

A stable identity envelope for the machine: ID, layered fingerprints (software/config), policies, and chain genesis hash (append-only linkage).

D2 — Evidence Log (append-only)

Raw events + ΦΩ propositions + evidence records chained by hashes (tamper-evident). Delivered as a portable archive.

D3 — Deterministic Verify

Verification procedure/tooling: input record/hash → deterministic output (MATCH / NO MATCH) and traceable timeline.

D4 — Pilot Report

Technical report describing identity, event taxonomy, critical incidents, continuity metrics, and readiness for EU audit pipelines and future signature/time-stamping upgrades.

4) Event coverage (baseline)

Baseline event taxonomy includes lifecycle, safety, operation, and (if present) AI decision events: BOOT/SHUTDOWN, MODE_CHANGE, CONFIG_CHANGE, E_STOP, SAFETY_TRIP, HUMAN_OVERRIDE, FAULT/RECOVERY, JOB_START/JOB_END, AI_DECISION/POLICY_DENY.

Final event list is refined during Week 1 based on the actual machine interface/logs.

5) Requirements (from the host organization)

  • One real target system: robot / PLC / cell (production or test environment).
  • Read-only access to logs or event export (file, syslog, gateway, or protocol read mode).
  • A technical contact for coordination (R&D / automation / OT engineer).
  • Optional: NDA before sharing any internal identifiers (serial/MAC/config exports).

6) Timeline (30 days)

Week 1 — Setup & Identity

  • Confirm input channel(s) (export/syslog/gateway).
  • Emit MIP (identity + fingerprints + genesis).
  • Finalize event mapping for the target system.

Week 2–3 — Evidence logging

  • Continuous capture of baseline events.
  • Hash-chain integrity monitoring (append-only).
  • Critical event review (faults, overrides, safety trips).

Week 4 — Verification & Report

  • Deterministic verification procedure/tooling delivery.
  • Final evidence pack export.
  • Pilot report delivery and debrief.

7) Commercial notes (pilot-ready)

Pilot pricing is typically in the €3k–€8k range for a 30-day validation (Laptop Mode), depending on integration complexity and the number of event channels.

The pilot can be delivered as OPPONIBLE_READY (technical signing + deterministic verification), with optional upgrades to qualified signing/time-stamping and long-term archival workflows.
