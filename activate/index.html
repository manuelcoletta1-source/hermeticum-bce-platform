Identity entry path of the HBCE system

Activate is the identity entry path of the HBCE system. It defines how local release creation, public proof publication, and deterministic verification connect before infrastructure participation becomes valid.

Identity is not treated as a decorative account layer. It is the condition required for attributable actions, registry state, and later governance.

Activate vs Create

ACTIVATE

Entry discipline

Activate defines the identity entry sequence and the relationship between local release, registry proof, and verification.

CREATE

Release generation

Create generates the local release object under holder custody. Public exposure remains hash-only through the registry layer.

Canonical sequence

The entry path is sequential. Identity becomes operational only when local generation, public proof, and deterministic validation converge.

Joker-C2 Architecture

Fail-closed rule

If deterministic identity proof cannot be reproduced through local release content, public registry proof, and verification logic, the correct state is failure. Infrastructure participation must remain blocked.
