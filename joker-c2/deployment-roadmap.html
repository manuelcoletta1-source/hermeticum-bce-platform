Roadmap model

The roadmap is intentionally narrow. It does not attempt to deploy the entire MATRIX architecture. It focuses on one commercially understandable workflow: 

Document upload
→ AI analysis
→ governance decision
→ human validation
→ EVT event
→ OPC proof
→ audit report

This workflow can be tested first internally, then with a small external pilot, before any enterprise or institutional hardening is considered.

Stage 1 — Internal R&D self-pilot

Objective: prove that HERMETICUM B.C.E. S.r.l. can use its own runtime to generate an audit-ready AI document workflow.

STEP 01

Select documents

  • Use owned, public, synthetic or authorized documents.
  • Avoid secrets, private keys, identity documents and sensitive payloads.
  • Start with governance, compliance, security and audit documents.
STEP 02

Run MVP workflow

  • Upload document.
  • Run AI audit analysis.
  • Review governance decision and risk class.
  • Approve, correct or reject the AI output.
STEP 03

Export report

  • Generate EVT event.
  • Generate OPC proof.
  • Export TXT / JSON report.
  • Record findings for pilot review.
OUTCOME

HERMETICUM B.C.E. S.r.l. obtains an internal set of audit-ready reports demonstrating that AI-assisted document analysis can be traced, attributed, human-validated and exported.

Stage 2 — 30-day external pilot

Objective: test the same workflow with a small external user profile after the internal self-pilot is stable.

WEEK 1

Setup and scope

  • Select one organization or advisor profile.
  • Select one document workflow.
  • Define allowed document types and data boundaries.
  • Use 10–20 synthetic, public or authorized documents.
WEEK 2–3

Run pilot workflow

  • Run repeated AI document analysis.
  • Generate governance decisions and human validations.
  • Export audit reports.
  • Collect usability and reporting feedback.
WEEK 4

Review and evaluation

  • Review report clarity.
  • Review risk and validation workflow.
  • Review EVT / OPC readability.
  • Prepare external pilot evaluation summary.
OUTCOME

A small pilot package showing whether the MVP is understandable, repeatable and valuable for compliance, cybersecurity, legal operations, internal audit or AI governance workflows.

Stage 3 — Product hardening

Objective: identify what is required before positioning the MVP as a more complete product or SaaS candidate.

TECHNICAL

Runtime integration

  • Connect MVP analysis to the live AI JOKER-C2 API route.
  • Improve AI output quality.
  • Add persistent report storage if needed.
  • Add report verification endpoint if needed.
SECURITY

Controlled data handling

  • Define retention rules.
  • Define authentication and access control.
  • Block sensitive uploads.
  • Review private evidence handling.
COMMERCIAL

Offer design

  • Define target customer profile.
  • Define 30-day pilot package.
  • Define report deliverables.
  • Prepare pricing and onboarding assumptions.
OUTCOME

A clearer path toward productization, while preserving R&D boundaries and avoiding premature enterprise, compliance or regulatory claims.
