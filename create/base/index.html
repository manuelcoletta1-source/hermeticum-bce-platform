Create IPR Base (Release File)

The IPR Base is generated locally. The public network stores only hash-only proofs. This page defines the minimal release workflow required for Registry + Verify.

Output

What you produce

1) IPR Release File

A local file under the owner control (device / repository / private storage). It may contain identity metadata depending on your internal policy.

File example: IPR_BASE_RELEASE.json
Storage: local (owner-controlled)

2) Hash-only Proof

A deterministic hash of the release payload. This is the only data intended for the public registry.

Proof example: payload_sha256 = SHA-256(release_file_bytes)

3) Verification Readiness

Deterministic verification requires: (a) release file, (b) registry proof. Missing one of them → INVALID (fail-closed).

Minimal release schema

Required fields (recommended minimal set)

Keep public exposure at minimum. Public registry should store only the hash-only proof. The release file is owner-controlled and can include additional fields as needed.

Release (local)

  • proto (e.g., HBCE-CORE-v3)
  • kind (e.g., IPR_BASE_RELEASE)
  • issuer (HERMETICUM B.C.E. S.r.l.)
  • jurisdiction (EU)
  • policy[] (HASH_ONLY, APPEND_ONLY, FAIL_CLOSED, UE_FIRST, AUDIT_FIRST, GDPR_MIN)
  • timestamp (ISO 8601)
  • payload (owner-controlled content)

Registry entry (public)

  • payload_sha256 (required)
  • timestamp (required)
  • name (optional, strongly minimized)

Failure mode

Any missing required field or mismatch in deterministic computation is a hard failure:

INVALID → BLOCK EXECUTION
Operator note

Operator path depends on IPR validity

Operator access is gated. The operator role is not identity: it is authorization and responsibility. A valid IPR Base is mandatory before any operator issuance/validation workflow.
