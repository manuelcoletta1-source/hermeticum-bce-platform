Issuance outputs (what is generated)

CREATE produces three artifacts. Two are private (custody by the customer). One is public but hash-only.

Artifact Custody Purpose
IPR Release (file) Private (local) Operational identity proof. Required to verify integrity.
Receipt (evidence) Private (local) Issuance record: shows what was issued and when.
Registry Entry (hash-only) Public (append-only) Minimal proof for deterministic verification (GDPR-min).
Public minimization: the registry stores only label + payload_sha256 + timestamp. No personal data is stored publicly.

Fail-closed policy

  • If Release integrity cannot be proven → INVALID
  • If hash is not present in registry → INVALID
  • If VERIFY cannot run deterministically → INVALID

There is no “partial validity”. Operational access is binary: VALID or BLOCK.

Who does what (customer vs operator)

Customer

Local custody + verification

  • Keep Release + Receipt securely (local custody)
  • Request append-only publication of the hash-only entry
  • Run VERIFY to obtain deterministic status
  • Use VALID IPR to activate tools and network
HBCE Certified Operator

Issuance + registry append governance

  • Perform issuance discipline (Release + Receipt + entry)
  • Append hash-only entry to the public registry (append-only)
  • Ensure audit-ready evidence packs
  • Support node operations (territorial scaling)

Operator status is a licensed role. It is not automatic. It requires compliance discipline and auditability.

Registry entry (hash-only) — format

The registry entry is the only public artifact. It must be append-only. The exact registry schema is defined in the registry package.

Example (template)
{ "name": "LABEL (minimal public label)", "payload_sha256": "64-hex sha256", "timestamp": "ISO-8601 UTC" }

Public label should be minimal. Private identity is inside the Release file, not the registry.

Integrity requirement

If payload_sha256 is missing or invalid → registry is considered invalid for the entry (fail-closed).

Next step: VERIFY (deterministic)

After the hash-only entry is appended to the registry, verification can be executed deterministically. The result is binary: VALID or INVALID.

  • Input: Release file (private) + registry entry (public hash-only)
  • Process: compute SHA-256 and compare with registry presence
  • Output: VALID or INVALID (fail-closed)
