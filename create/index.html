Create or prepare an IPR record.

This page is the preparation gateway for IPR — Identity Primary Record. It is used to start or structure an operational identity record before final verification, activation and IPR Card issuance.

Create does not automatically produce a verified identity. Create does not automatically issue an active IPR Card. Create does not automatically grant governed access to JOKER-C2.

The correct purpose of this page is to move from an initial preparation state toward a controlled pending state: IPR_DRAFT → IPR_PENDING. The next step, handled by activation and review, is IPR_PENDING → IPR_ACTIVE.

CREATE VS ACTIVATE

Create prepares. Activate verifies and enables.

The HBCE Platform separates preparation from activation. This distinction prevents a simple form submission from being interpreted as a verified operational identity.

CREATE

Preparation state

registration data
→ subject type
→ context
→ draft IPR structure
→ private evidence boundary
→ proof preparation
→ IPR_DRAFT / IPR_PENDING

Create can prepare the record, the evidence boundary and the proof references. It must not claim that the subject is already verified.

→ policy check
→ activation EVT
→ OPC receipt
→ IPR_ACTIVE

Activate is the later stage where verification, review, proof and access-state logic can produce an active operational identity.

WHAT CREATE IPR MEANS

Creating an IPR means preparing an operational identity record.

Creating an IPR means preparing a structured operational record that can later be connected to identity evidence, role, operation, event, proof, responsibility and continuity. It is not the same as issuing official identity or granting runtime access. 

IPR preparation =
subject reference
+ subject type
+ role or context
+ intended operation
+ private verification boundary
+ proof preparation
+ pending state

A prepared IPR can become useful only when it is connected to controlled verification, activation, EVT continuity, OPC proof and fail-closed access logic.

Creation sequence

STEP 01

Define subject

Identify whether the IPR refers to a natural person, legal entity, operator, company, institution, professional, researcher, AI system, node, process or document workflow.

STEP 02

Define context

Define the role, organization, project, workflow, operation or runtime context in which the IPR is being prepared.

STEP 03

Prepare evidence boundary

If the IPR requires verification, prepare the private evidence boundary. Sensitive identity evidence must not be placed in the public registry.

STEP 04

Create draft structure

Generate or prepare the IPR record structure, including reference, subject type, intended scope, status and proof preparation fields.

STEP 05

Generate proof reference

Prepare hash-oriented proof material, evidence-pack references or draft EVT/OPC links where appropriate for R&D or controlled workflows.

STEP 06

Move to pending review

If the record is submitted for verification, its correct state is IPR_PENDING until activation review is completed.

STATE MODEL

Create handles draft and pending states.

A creation flow must be stateful. It should clearly distinguish between a draft, a submitted pending record and an active verified record. 

IPR_DRAFT
→ record started, incomplete or not submitted

IPR_PENDING
→ record submitted or prepared for review

IPR_REVIEW_REQUIRED
→ correction, escalation or human review required

IPR_ACTIVE
→ verified operational identity after activation review

IPR_SUSPENDED
→ temporary restriction

IPR_REVOKED
→ no longer valid

IPR_EXPIRED
→ renewal required

This page should not claim to create IPR_ACTIVE directly. IPR_ACTIVE belongs to activation, review and verification logic.

PRIVATE VERIFICATION BOUNDARY

Create may prepare verification. It does not publish identity evidence.

The IPR model separates private verification from public proof. If identity evidence is required, it belongs to a private or controlled verification package, not to the public registry or public repository.

PRIVATE OR CONTROLLED
  • Tax code where applicable
  • National tax identifier
  • National identification number
  • Identity document number
  • Passport number
  • Driving-license number
  • Residence permit number
  • Identity document scan
  • Selfie or portrait image

OUTPUT OF CREATE

Create prepares the record, not final access.

A correct Create flow may produce draft record data, a pending IPR structure, hash-oriented proof material or a controlled evidence package. It should not claim full access capability.

- draft subject reference

LEGAL BOUNDARY

Create IPR does not create official identity.

This page is part of the HBCE R&D reference platform. It does not create a public legal identity, does not replace SPID, CIE, EUDI Wallet, eIDAS schemes, digital signatures or public registries, and does not provide legal certification or regulated trust-service status by itself.

Any real production onboarding, document verification, liveness detection, biometric comparison, enterprise deployment, public-sector use or institutional integration requires separate legal, privacy, cybersecurity, compliance and operational review.

Do not publish identity documents, tax codes, national identifiers, document numbers, private keys, credentials or sensitive operational payloads in the public repository, registry or public demo flows.
