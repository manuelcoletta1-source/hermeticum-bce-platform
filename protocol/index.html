IPR / HBCE protocol references

The Protocol section contains R&D technical references for IPR-linked evidence, HBCE public proof, operational identity, event records, proof records, node concepts, registry semantics and verification logic.

These files are not a formal legal standard, not regulated technical certification, not public authority approval, not eIDAS qualification and not a production compliance framework by themselves.

CURRENT TECHNICAL POSTURE

The current platform hierarchy is IPR-first. IPR is the base operational product, IPR AI Audit Trail is the first MVP use case, HBCE is the operational ecosystem, JOKER-C2 is the runtime demonstrator and MATRiX is the broader architectural framework.

The current public proof model is based on registry v3, payload_sha256, minimized public records, hash-oriented proof commitments, append-only history, no-public-data-custody boundaries and fail-closed verification.

Older v1 protocol files are retained as historical or R&D references unless explicitly updated. New implementation work should align with the current IPR-first / registry v3 / schema v2 direction.

6. Protocol posture

STRUCTURED

Minimal technical definitions

Research structures should be explicit, reviewable and consistent with IPR-first positioning.

APPEND-ONLY

Chronological consistency

Public record history should be extended, not silently rewritten.

FAIL-CLOSED

No implicit validity

Missing, malformed or unverifiable state must not produce validity.

EU-FIRST

Governance reference

EU-first is a governance posture, not formal regulatory certification.
