3. Public proof concept

If a future operator-proof workflow is implemented, public records should follow the current HBCE public proof model: registry v3, payload_sha256, minimized labels, append-only discipline and fail-closed verification.

The public record should not contain name, raw identity material, identity documents, tax codes, credentials, private keys, private evidence, production logs, customer data or sensitive operational payloads.

Public proof presence does not equal operator authorization. It only indicates that a minimized public proof commitment exists.

4. Future issuance concept

A future operator authorization process, if developed, would require separate controls beyond this static page.

  • legal review;
  • security review;
  • privacy review;
  • identity verification process;
  • role and responsibility definition;
  • contractual qualification;
  • revocation and suspension policy;
  • persistent storage and audit retention;
  • human approval and evidence review;
  • clear distinction between public proof and private evidence.
