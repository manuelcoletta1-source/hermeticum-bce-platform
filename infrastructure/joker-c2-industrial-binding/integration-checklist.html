Integration principle:
Put the gateway in front of execution. If no verified identity → no token → no action.

Pick your integration profile

P1

API Gate

For systems where robots/fleets accept commands through APIs. Gateway is a reverse-proxy / command broker in front of the API.

P2

ROS2 Gate

For robotics stacks using ROS2. Gateway is a ROS2 node that authorizes actions before publishing allowed commands.

P3

Industrial Bridge

For factories: MES/SCADA/OPC-UA → gateway → PLC/robot controller. Add authorization and audit proofs in the execution corridor.

P1 — API Gate checklist

  1. Identify the command API endpoints used for execution.
  2. Place the Binding Gateway as the only reachable command entry point (allowlist).
  3. Map command types to risk classes (LOW/MED/HIGH).
  4. Implement token requirement: controller accepts execution only with valid token.
  5. Enable evidence pack generation and periodic hash-only proof emission.
  6. Run demo scenarios (allow/deny, threshold deny, approvals).
Good for
  • Fleet managers
  • Drones
  • Software-controlled robots
  • Cloud robotics APIs

P2 — ROS2 Gate checklist

  1. Identify ROS2 actions/services that trigger motion/critical operations.
  2. Insert gateway node: it receives ActionRequest and decides ALLOW/DENY.
  3. Publish only allowed commands on separate topics (or guarded action server).
  4. Bind telemetry snapshot hashes for high-risk actions (optional but strong).
  5. Enable evidence pack + hash-only proof.
  6. Run reproducible verification path.
Good for
  • Humanoid research platforms
  • Advanced robotics R&D
  • ROS2-based autonomy stacks

P3 — Industrial Bridge checklist

  1. Identify execution corridor: MES/SCADA/OPC-UA → PLC/robot controller.
  2. Place gateway in the corridor and block direct write paths (segmentation).
  3. Define high-risk operations (override, parameter change, mode switch).
  4. Enforce dual approval where required.
  5. Enable local ledger for resilience (factory network outages).
  6. Emit hash-only proofs periodically; verify reproducibility.
Good for
  • Robot cells
  • Automation lines
  • Critical maintenance ops
  • Procurement-grade auditing

Success criteria (pilot acceptance)

  • At least one critical action is gated (no token → no execution).
  • Allow/Deny scenarios are reproducible with deterministic verification.
  • Evidence packs are generated under customer custody.
  • Hash-only proofs are emitted in append-only mode.
  • Bypass paths are mitigated (network posture, allowlists).
