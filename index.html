IPR — Identità operativa verificabile nel tempo

Un IPR (Identity Primary Record) è un file rilasciato che genera una prova pubblica minima: nickname + hash + timestamp in un registry append-only. Se non è verificabile → INVALID.

Crea IPR Base (local-first) Cos’è IPR Verifica

Pubblico = hash-only. Nessun dato personale nel registry. Nessuna custodia identitaria.

Regola operativa: SOFT vs HARD

BASE (SOFT)

Per il cittadino UE che vuole iniziare: nessun vincolo temporale. Se l’hash è presente nel registry append-only → VALID (SOFT).

Pacchetto tipico: BASE_19.

EU/CERT (HARD)

Per emissioni con garanzia metrologica: finestra ±2 minuti per append nel registry. Fuori finestra → INVALID (HARD) (fail-closed).

HARD è per pacchetti certificati/istituzionali, non per l’onboarding base.

REGISTRY (append-only)

L’entry pubblica è hash-only: nickname + payload_sha256 + timestamp. Si aggiunge al registry senza cancellare nulla.

VERIFY (fail-closed)

Verifica in due modi: by hash (prova pubblica) oppure by file (integrità locale + match registry). Se non c’è match → INVALID.

4

UPGRADE (opzionale)

Dopo la base puoi aggiungere ancoraggi (IPFS/EVM/BTC) o moduli software (UNEBDO, OPC, ecc.). La prova pubblica resta minimizzata.

Pacchetti Ecosystem

Regola unica: CREATE → REGISTRY → VERIFY. Se salti REGISTRY, VERIFY non può passare.

Perché serve

Cittadini e professionisti

Una radice minimale, verificabile, che abilita evoluzioni operative senza trasformare il portale in un database di persone.

Imprese e istituzioni (B2B/B2G)

Identità operative per software, AI, robotica e sistemi critici: verificabili ex-ante, auditabili, fail-closed.
