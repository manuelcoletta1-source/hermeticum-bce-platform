Cos’è (senza filosofia, solo ingegneria)

Identità civile ≠ identità operativa

CIE/SPID/eIDAS descrivono chi sei. IPR descrive cosa può agire in modo verificabile nel tempo: persone, AI, robot, organizzazioni, processi.

IPR non sostituisce eIDAS: aggiunge un livello operativo ex-ante (pre-esecuzione).

Fail-closed = sicurezza reale

Se manca la prova minima (hash) o il match nel registry, il sistema non “interpreta”: blocca. Risultato deterministico: VALID / INVALID.

“FAIL” non è errore: è protezione strutturale.

Accesso operativo (Base → Operatore, chained)

1) IPR Base EU — Entry

Baseline tecnica. Senza Base VALID non esiste nessun livello successivo.

  • Artefatti: IPR_RELEASE (privato) + REGISTRY_ENTRY (pubblico)
  • Validità: match su registry pubblico (hash-only)
  • Regola: se non matcha → INVALID (fail-closed)
CREA BASE APPEND VERIFY

2) IPR Operatore EU — License (requires Base VALID)

L’operatore è una licenza collegata alla Base dell’operatore. Se la Base non è in registry → BLOCK.

  • Input obbligatorio: IPR_RELEASE Base dell’operatore
  • Check 1: integrità SHA-256(payload)
  • Check 2: match Base nel registry pubblico
  • Output: OPERATOR_LICENSE (privato) + REGISTRY_ENTRY (pubblico)
CREA OPERATORE WORKSTATION

Decisione–Costo–Traccia–Tempo: la traccia (registry match) è la condizione di esistenza operativa. Il pagamento verrà messo come gate prima del rilascio (non prima della verifica).

Flusso operativo (meccanica minima)

Pipeline: CREATE → RECEIPT → REGISTRY(APPEND) → VERIFY

CREATE genera il payload e calcola SHA-256 localmente (no custody). RECEIPT produce una entry hash-only pronta da appendere. REGISTRY (append-only) rende pubblica la prova minimizzata. VERIFY determina VALID / INVALID.

1 — CREATE 2 — RECEIPT 3 — APPEND 4 — VERIFY

Pubblico: name/nickname + hash + timestamp. Privato: release/license file.
