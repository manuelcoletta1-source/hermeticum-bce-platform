ENFORCEMENT (regola dura)

HERMETICUM non “valuta” a sentimento. Applica regole deterministiche. La verifica è un confronto: match o no.

  • Verifica deterministica → VALID / INVALID
  • Pubblico = proof-only (hash-only)
  • Registro = append-only (niente riscritture)
NON-COMPLIANCE (conseguenze)

Se una condizione fallisce, non c’è “mezzo valido”. C’è solo blocco operativo.

  • Fonte non leggibile → FAIL-CLOSED
  • Hash non matcha → INVALID
  • Minimizzazione violata → BLOCK
  • Identità non validabile → ACCESS DENIED
AUDIT (ricostruibilità)

Ogni prova è ricostruibile nel tempo. L’audit non è un optional: è la base.

  • Proof hash-only pubblica
  • Determinismo ripetibile
  • Storia append-only
