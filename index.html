Significato e ordine (infrastruttura, non filosofia)

Che cos’è davvero

L’IPR (Identity Primary Record) è un registro operativo persistente. Non è account, non è documento, non è piattaforma: è la continuità verificabile di un’entità nel tempo. 1

Identità civile (CIE/SPID/eIDAS) definisce “chi sei”. IPR definisce “cosa può agire” con prova e audit. 2

Ordine di realtà (fail-closed)

L’infrastruttura esiste solo se la prova minimizzata è presente e verificabile: match su registry → VALID; assenza match / errore → INVALID/FAIL-CLOSED.

“FAIL” non è errore: è protezione strutturale (nessuna esecuzione silente).

Accesso operativo (ordine non negoziabile)

1) IPR Base EU — Entry

Baseline tecnica. Senza Base VALID non esiste nessun livello successivo.

  • Artefatti: IPR_RELEASE (privato) + REGISTRY_ENTRY (pubblico)
  • Validità: match su registry pubblico (hash-only)
  • Regola: se non matcha → INVALID (fail-closed)
CREA BASE APPEND VERIFY

2) IPR Operatore EU — Licenza (richiede Base VALID)

L’operatore è una licenza collegata alla Base dell’operatore. Se la Base non è in registry → BLOCK.

  • Input: IPR_RELEASE Base dell’operatore
  • Check 1: integrità SHA-256(payload)
  • Check 2: match Base nel registry pubblico
  • Output: OPERATOR_LICENSE (privato) + REGISTRY_ENTRY (pubblico)
CREA OPERATORE WORKSTATION

Decisione–Costo–Traccia–Tempo: la traccia (registry match) è condizione di esistenza operativa.

Flusso operativo (meccanica minima)

Pipeline: CREATE → RECEIPT → REGISTRY(APPEND) → VERIFY

CREATE genera il payload e calcola SHA-256 localmente (no custody). RECEIPT produce una entry hash-only pronta da appendere. REGISTRY (append-only) rende pubblica la prova minimizzata. VERIFY determina VALID / INVALID.
