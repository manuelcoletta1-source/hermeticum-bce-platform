R&D verification utilities

The Tools area collects technical utilities used to inspect, test, and harden the public HBCE registry surface. The current scope is the MATRIX AI Audit Trail MVP, with emphasis on registry v3, privacy-minimal public proof records, deterministic verification, link integrity, and fail-closed behavior.

These tools are R&D utilities. They are not regulated certification engines, not public authority services, not eIDAS qualified trust services, not custodial identity services, and not production compliance frameworks by themselves.

Current boundary

The tools in this section support technical inspection and R&D validation only. A successful tool result may indicate structural consistency, public-link availability, or registry-shape compliance, but it does not create legal validity, cybersecurity assurance, public authority approval, regulated compliance, operator qualification, or production authorization. 

R&D TOOLING BOUNDARY
- EU reference framework
- MATRIX AI Audit Trail MVP
- hash-only public proof model
- privacy-minimal registry records
- no public data custody
- no private key custody
- no regulated certification claim
- no public authority claim
- fail-closed validation posture

Forbidden public-data patterns

Tool outputs and public registry artifacts must not expose private operational material. Public proof must remain minimized and hash-only whenever possible. 

FORBIDDEN IN PUBLIC TOOLING / REGISTRY ARTIFACTS
- secrets, tokens, passwords, credentials, API keys
- private keys, SSH keys, database URLs, admin URLs
- identity documents or raw personal identifiers
- raw AI prompts or raw AI outputs
- client files or confidential payloads
- production logs or private communications
- internal endpoints, private IPs, internal hostnames
- sensitive infrastructure topology
