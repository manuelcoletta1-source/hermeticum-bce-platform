Platform control utilities for the IPR onboarding spine.

The Tools area collects technical utilities used to inspect, test and harden the public HBCE Platform. Its current operational role is to support the route spine: Platform → IPR Onboarding App → Onboarding → IPR → IPR Card → JOKER-C2 → IPR AI Audit Trail → Registry / Verify.

The central tool is Tool Link Audit, used to check public route reachability, broken internal links, legacy route patterns, actionable legacy text references, expected guardrail references and the active Platform spine.

These tools are R&D utilities. They are not regulated certification engines, not public authority services, not eIDAS qualified trust services, not custodial identity services, not KYC / AML services and not production compliance frameworks by themselves.

TOOLING BOUNDARY

Current tooling boundary

The tools in this section support technical inspection and R&D validation only. A successful tool result may indicate structural consistency, public-link availability, registry-shape compliance, local hash consistency or evidence-pack integrity, but it does not create legal validity, cybersecurity assurance, public authority approval, regulated compliance, operator qualification, official identity status, production authorization or JOKER-C2 access.

Forbidden public-data patterns

Tool outputs and public registry artifacts must not expose private operational material. Public proof must remain minimized and hash-only whenever possible. 

FORBIDDEN IN PUBLIC TOOLING / REGISTRY ARTIFACTS
- secrets, tokens, passwords, credentials, API keys
- private keys, SSH keys, database URLs, admin URLs
- identity documents or raw personal identifiers
- tax codes or document numbers
- raw AI prompts or raw AI outputs
- client files or confidential payloads
- production logs or private communications
- internal endpoints, private IPs, internal hostnames
- sensitive infrastructure topology
TOOL RESULT INTERPRETATION

Tool results are technical signals, not regulated approvals.

Link integrity, registry shape, hash match, proof presence or schema consistency are technical signals. They support audit readiness and diagnostic control, but they do not replace legal review, privacy review, cybersecurity review, public authority validation, identity verification, contractual approval or production readiness. 

HASH_MATCH
→ technical equality only

PUBLIC_REFERENCE_PRESENT
→ public proof reference exists only

LINK_AUDIT_PASS
→ configured public route layer clean only

REGISTRY_OPERATIONAL
→ registry source accepted by R&D guardrails only

None of these states equals:
→ legal certification
→ official identity issuance
→ eIDAS qualification
→ KYC / AML compliance
→ public authority approval
→ JOKER-C2 production access
