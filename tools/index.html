R&D verification utilities for IPR public proof workflows

The Tools area collects technical utilities used to inspect, test and harden the public HBCE registry and verification surface. The current operational focus is IPR, with the first MVP represented by IPR AI Audit Trail.

These tools support registry v3 checks, privacy-minimal public proof review, deterministic verification, public link integrity, evidence-pack consistency and fail-closed diagnostics. MATRIX remains the wider architectural framework, while IPR remains the first operational product.

These tools are R&D utilities. They are not regulated certification engines, not public authority services, not eIDAS qualified trust services, not custodial identity services, and not production compliance frameworks by themselves.

Registry Guard

registry-guard.js is a repository-side validation utility for registry v3. It helps enforce privacy-minimal public records, forbidden-field rejection, hash-only proof expectations and fail-closed registry behavior.

Current tooling boundary

The tools in this section support technical inspection and R&D validation only. A successful tool result may indicate structural consistency, public-link availability, registry-shape compliance, local hash consistency or evidence-pack integrity, but it does not create legal validity, cybersecurity assurance, public authority approval, regulated compliance, operator qualification or production authorization. 

R&D TOOLING BOUNDARY
- EU reference posture
- IPR-first product hierarchy
- IPR AI Audit Trail MVP
- hash-only public proof model
- privacy-minimal registry records
- no public data custody
- no private key custody
- no regulated certification claim
- no public authority claim
- fail-closed validation posture

Forbidden public-data patterns

Tool outputs and public registry artifacts must not expose private operational material. Public proof must remain minimized and hash-only whenever possible. 

FORBIDDEN IN PUBLIC TOOLING / REGISTRY ARTIFACTS
- secrets, tokens, passwords, credentials, API keys
- private keys, SSH keys, database URLs, admin URLs
- identity documents or raw personal identifiers
- tax codes or document numbers
- raw AI prompts or raw AI outputs
- client files or confidential payloads
- production logs or private communications
- internal endpoints, private IPs, internal hostnames
- sensitive infrastructure topology
