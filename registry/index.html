Public proof registry

The Registry is the public proof layer of the HBCE stack. It exposes minimized public evidence through an append-only, hash-only ledger used by deterministic verification workflows.

If the registry source is unreachable, malformed, invalid, inconsistent, or non-deterministic, the correct system posture is NON-OPERATIONAL.

POSITION IN THE STACK

In the HBCE architecture: IPR provides attribution, Joker-C2 governs execution, Registry publishes public proof, and Verify reproduces deterministic validation.

Registry rule

The registry is append-only and public-facing in hash-only form. Historical evidence is extended, not rewritten. Personal data must not be published into the public ledger. 

(rules will be displayed here when registry loads)

Public data minimization

Public identity labels may appear only when intentionally published for attribution and registry readability. Sensitive identity evidence, private documents, credentials, private keys, and non-public payloads must not be stored in the public registry. 

PUBLIC REGISTRY RULES
- public proof only
- hash-only or minimized metadata
- no private evidence custody
- no secrets
- no private keys
- no identity documents
- no production logs
- no sensitive operational payloads
- missing or invalid source → NON-OPERATIONAL
