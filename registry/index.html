REGISTRY · PUBLIC PROOF SURFACE · IPR · IPR CARD · EVT · OPC · HASH-ONLY · FAIL-CLOSED

Registry proves public reference presence. It does not prove official identity.

The Registry is the minimized public proof-reference surface for IPR records, IPR Card public references, activation EVT records, OPC proof receipts and audit-oriented evidence inside the HBCE ecosystem.

The registry may expose public proof references such as IPR reference, status, verification level, proof scope, payload hash, activation EVT, OPC reference, timestamp and non-sensitive public label. It must not expose tax codes, national identifiers, document numbers, identity documents, scans, portraits, selfies, liveness videos, addresses, dates of birth, private evidence, customer files, personal payloads, credentials, secrets or sensitive operational material.

A registry match means only that a public proof reference exists. It does not certify legal identity, official European identity, regulated KYC / AML compliance, public authority approval, eIDAS qualification, cybersecurity assurance, production authorization or JOKER-C2 access by itself.

PUBLIC BOUNDARY

Public records must remain minimized. The correct public pattern is private verification or controlled evidence outside the public repository, then hash-oriented proof reference, then registry entry, then deterministic verification. 

private verification package
→ IPR / IPR Card / activation EVT / OPC receipt
→ public hash reference
→ registry minimized entry
→ verify

IPR Verified and IPR Card rely on private or controlled verification. The public registry can record that a minimized proof reference exists, but it cannot certify legal identity, regulated KYC / AML compliance, public authority approval, eIDAS qualification, operator qualification or production authorization.

EVIDENCE SEQUENCE

IPR / IPR Card evidence sequence

The registry supports IPR Base, IPR Verified, IPR Card, activation EVT, OPC proof and IPR AI Audit Trail by exposing minimized public references to private or controlled audit material. 

PRIVATE_VERIFICATION_PACKAGE
→ IPR_OPERATIONAL_REFERENCE
→ IPR_CARD_REFERENCE
→ ACTIVATION_EVT
→ OPC_RECEIPT
→ HASH_ORIENTED_PUBLIC_REFERENCE
→ OPTIONAL_PUBLIC_REGISTRY_ENTRY
→ VERIFY
→ FAIL_CLOSED_REVIEW

This sequence creates technical audit visibility without requiring public custody of tax codes, national identifiers, document numbers, identity documents, confidential prompts, outputs, review notes, evidence payloads, client files or regulated personal data.

ACCESS BOUNDARY

Registry presence is not JOKER-C2 access.

A registry entry can support public proof-reference verification, but it does not automatically authorize JOKER-C2 access. Runtime access depends on IPR status, verification level, policy, risk and access-state logic. 

registry public reference present
→ proof reference exists

IPR_ACTIVE + policy pass
→ access may be allowed

missing / malformed / ambiguous proof
→ fail-closed

PENDING / SUSPENDED / REVOKED / EXPIRED
→ no governed runtime access
