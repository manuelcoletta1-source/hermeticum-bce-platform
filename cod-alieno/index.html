COD ALIENO

Specifica operativa “ultima” del motore IO-SPACE per la certificazione di eventi opponibili. Questo documento è progettato per essere applicabile: definisce campi, regole, output e failure-mode.

Apri IO-SPACE VERIFY REGISTRY

Principi operativi

IO-SPACE opera solo se la base è verificabile. In caso contrario: FAIL-CLOSED.

  • UE-FIRST: baseline normativa UE
  • AUDIT-FIRST: ogni output deve essere ispezionabile
  • HASH-ONLY: pubblicazione minimizzata (prove, non dati)
  • APPEND-ONLY: registri senza riscritture
  • FAIL-CLOSED: se manca integrità o match → INVALID
  • NO PUBLIC DATA CUSTODY: nessuna custodia pubblica di dati personali

IO-SPACE — che cosa certifica

IO-SPACE genera un Event Manifest e un event_hash derivato in modo deterministico. L’evento diventa opponibile quando è collegabile a un IPR valido e registrabile in modalità append-only.

  • Decisioni operative
  • Azioni su sistemi (AI/robot/infrastrutture)
  • Comandi e transazioni tecniche
  • Emissioni/certificazioni che richiedono tracciabilità

Event Manifest — struttura canonica

Campi minimi per un evento certificabile. Tutto ciò che non è necessario va escluso (GDPR-min). 

{
  "proto": "HBCE-IO-SPACE-EVENT-v1",
  "kind": "OPPONIBLE_EVENT",
  "issuer": "HERMETICUM B.C.E. S.r.l.",
  "network": "EU",
  "policy": ["UE_FIRST","AUDIT_FIRST","FAIL_CLOSED","HASH_ONLY","APPEND_ONLY","GDPR_MIN","NO_PUBLIC_DATA_CUSTODY"],

  "actor": {
    "ipr_payload_sha256": "<64-hex sha256>"
  },

  "event": {
    "event_type": "DECISION|ACTION|TRANSACTION|COMMAND",
    "scope": "LOCAL|REGIONAL|NATIONAL|EU|GLOBAL",
    "risk_class": "R0|R1|R2|R3|R4",
    "maturity_level": "L0|L1|L2|L3|L4|L5",
    "summary": "testo breve non sensibile",
    "ref_payload_sha256": "<optional: 64-hex sha256>"
  },

  "timestamp": "2026-02-17T00:00:00Z"
}

Nota: summary deve rimanere non sensibile. Se serve contenuto reale, va tenuto nel release file privato, e in pubblico si pubblica solo hash.

Regole di valutazione (maturità e responsabilità)

IO-SPACE è un motore di coerenza: più alto il livello, più alti requisiti e responsabilità.

  • risk_class (R0→R4): impatto potenziale dell’evento
  • maturity_level (L0→L5): complessità/criticità del dominio
  • Se R o L oltre soglia consentita dall’operatore → DENY (fail-closed)

Output deterministico

Output minimo: manifest + hash + snippet registrabile.

  • event_manifest (JSON canonico)
  • event_hash = sha256(canonical_json(event_manifest))
  • registry snippet hash-only per append nel registro pubblico
{
  "record_type": "STATUS_UPDATE",
  "ref_payload_sha256": "<event_hash>",
  "status": "CERTIFIED",
  "timestamp": "2026-02-17T00:00:00Z",
  "note": "IO-SPACE event certified (hash-only)"
}

FAIL-CLOSED — condizioni di blocco

  • IPR non valido / non verificabile nel registry
  • Manifest incompleto o non canonico
  • Timestamp non conforme (ISO 8601 UTC)
  • Ambiguità sui campi sensibili → blocco
  • Incoerenza tra rischio, maturità e permessi operatore

Integrazione nel portale

Percorso operativo standard (istituzionale):

  1. Attiva IPR (release file)
  2. Verifica IPR (VALID)
  3. Accesso operatore (gated)
  4. Genera evento in IO-SPACE
  5. Append hash-only nel registro eventi/registry
