2. Why the old form is removed

The previous version collected real name, email, IPR reference and location fields, then generated an operator-license application packet and a registry-style entry.

Even though it was local-first, the route could be misread as an active operator-license workflow. To avoid confusion with the current registry v3, payload_sha256, no-public-data-custody and R&D boundary model, the active application form has been removed from this legacy page.

Future operator qualification workflows, if developed, require separate legal, privacy, security, contractual and institutional review.

3. Current public proof model

Any future public operator proof should follow the current HBCE public proof model: 

Private or controlled evidence
→ canonical hash commitment
→ payload_sha256
→ registry v3 public record
→ deterministic verify
→ PUBLIC_RECORD_PRESENT / NO_PUBLIC_RECORD / INVALID / NON_OPERATIONAL

Public proof presence does not equal operator authorization. A public record only indicates that a minimized proof commitment exists.
