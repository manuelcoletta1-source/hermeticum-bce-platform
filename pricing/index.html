JOKER-C2 ACCESS BOUNDARY

Pricing does not mean automatic runtime access.

JOKER-C2 governed runtime access, where included or discussed, depends on IPR state, IPR Card status, verification level, policy, risk, operational authorization and the applicable pilot scope. 

No verified IPR
→ no governed runtime access

IPR_PENDING
→ review required

IPR_ACTIVE + policy pass + scope approved
→ access may be allowed

IPR_SUSPENDED / REVOKED / EXPIRED
→ access denied or renewal required

Runtime access does not create legal certification, compliance certification, identity certification, cybersecurity assurance, public authority approval or production authorization by itself.

PRIVATE VERIFICATION AND PUBLIC DATA BOUNDARY

Real identity data requires a separately scoped environment.

IPR Verified may use accepted identity evidence and national identifier evidence only in a controlled private verification layer. The public layer must never store tax codes, national identifiers, document numbers, identity documents, identity scans, selfies, liveness videos, personal payloads, customer personal data, credentials, secrets, private keys, confidential third-party data, production logs, private prompts, private outputs or regulated evidence requiring protected handling.

Any real-data deployment requires a separate environment with legal basis, data-processing terms, retention rules, access controls, security controls, responsibility owners and contractual scope.
