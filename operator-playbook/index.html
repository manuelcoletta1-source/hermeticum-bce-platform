Operator Playbook

Procedura ufficiale per emissione/certificazione IPR in HBCE. Obiettivo: passare da hash a opponibilità nel tempo tramite registry append-only e verify pubblico.

OPERATOR CONSOLE REGISTRY VERIFY GOVERNANCE

Regola sistema: se registry è assente o JSON invalido → INVALID (fail-closed).

Principi non negoziabili

  • Append-only: mai cancellare, mai riscrivere il passato
  • Hash-only: pubblico = nickname + hash + timestamp
  • No custody: nessun dato personale nel registry pubblico
  • Fail-closed: se non verificabile → blocco
  • Audit-first: tutto deve essere ricostruibile a posteriori

Procedura E2E (4 passaggi)

1) CREATE (cliente)

Il cliente genera localmente file + hash. Nessun invio server.

  • output: IPR_RELEASE.json
  • output: payload_sha256
OPEN CREATE OPEN WIZARD

2) CERTIFIED / REQUEST (post-pagamento)

La certificazione è il passaggio operativo: richiesta → controllo → registrazione. Qui si rilascia anche il documento “issuer certificate / ricevuta”.

OPEN CERTIFIED PRICING

3) REGISTRY APPEND (operatore)

L’operatore appende una entry in registry/registry.json, dentro entries[]. Solo dopo l’append, VERIFY può tornare VALID.

Entry valida = oggetto singolo con 3 campi: nickname, payload_sha256, timestamp. 

{
  "nickname": "ESEMPIO",
  "payload_sha256": "64-hex...",
  "timestamp": "2026-02-11T18:45:00.000Z"
}
OPEN REGISTRY OPEN CONSOLE

4) VERIFY (pubblico)

Il sistema confronta hash del file e match nel registry. Se non trova match → INVALID.

OPEN VERIFY

Errori tipici (che rompono tutto)

  • Doppie graffe dentro entries: { { ... } } → JSON invalido
  • Virgole mancanti o in eccesso → JSON invalido
  • Entry fuori da entries[] → registry incoerente
  • payload_sha256 non 64 hex → mismatch / invalid
  • Nickname vuoto → entry inutile (audit degrade)
  • Modificare vecchie entry → viola append-only (audit fail)

Se il registry è invalido: VERIFY entra in fail-closed e torna INVALID anche se “la hash è giusta”.

Checklist operatore (prima del commit)

  • Ho incollato solo l’oggetto entry dentro entries[]
  • Il file registry.json è JSON valido
  • Non ho cancellato o riscritto entry esistenti
  • Hash = 64 caratteri hex (0-9 a-f)
  • Timestamp ISO valido
  • Dopo push, VERIFY trova match
