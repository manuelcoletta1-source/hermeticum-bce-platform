IPR — Minimal Technical Reference

This page defines the current R&D technical reference for IPR — Identity Primary Record. It describes how the HBCE Platform treats operational identity, private verification, public proof minimization, registry references and fail-closed verification.

This page is not a formal legal standard, not a public authority standard, not an eIDAS qualified trust-service specification, not a regulated certification scheme and not a KYC / AML provider framework.

Current posture: R&D technical reference · IPR-first · IPR Verified · public proof minimization · fail-closed

IPR IPR Verified Registry Verify Claims

1. Scope

The purpose of this technical reference is to define a minimal and verifiable structure for IPR records inside the HBCE Platform.

The reference applies to R&D, MVP, pilot and documentation contexts. It does not create legal identity, regulated certification, public authority approval, eIDAS qualification, qualified trust-service status, KYC / AML provider status or production authorization. 

IPR = base operational product
IPR Base = technical R&D record, not verified identity
IPR Verified = private verification with tax code + valid identity document
IPR Professional = business / audit pilot profile based on IPR Verified
IPR AI Audit Trail = first MVP use case
HBCE = operational ecosystem
JOKER-C2 = runtime demonstrator
MATRiX = architectural framework

2. Definition

IPR means Identity Primary Record. It is an operational identity, attribution and proof record designed to connect a subject, role, operation, event, proof reference, responsibility and continuity into a verifiable technical trace.

IPR is not only a login, account, credential, signature, hash or registry entry. IPR is the operational reference that allows an event or workflow to be reconstructed later.

3. IPR profiles

PROFILE

IPR Base

IPR Base is a technical R&D record for proof flows, internal testing and controlled demonstrations. It does not create verified identity status.

Public level: IPR_BASE_NOT_VERIFIED

PROFILE

IPR Verified

IPR Verified is the private-verification profile. It may use tax-code and valid identity-document evidence only in a controlled private layer.

Public level: IPR_VERIFIED_PRIVATE_CHECK

PROFILE

IPR Professional

IPR Professional is a future business / audit workflow profile based on IPR Verified. It is intended for controlled B2B pilots and audit-ready evidence chains.

Public level: IPR_PROFESSIONAL_PILOT

4. Private verification model

IPR Verified may use private identity verification based on tax-code and valid identity-document evidence. Accepted private evidence categories are:

  • tax code / fiscal code;
  • identity card / CIE;
  • passport;
  • driving license;
  • private evidence package.

This material belongs only in the private verification layer. It must not be published in the public repository, public registry, public proof records, public issues, public pages or public demos. 

PRIVATE VERIFICATION
→ TAX CODE + VALID IDENTITY DOCUMENT
→ PRIVATE EVIDENCE PACKAGE
→ IPR VERIFIED RECORD
→ HASH-ORIENTED PUBLIC PROOF REFERENCE
→ REGISTRY / VERIFY / EVT / OPC

5. Public proof model

Public proof must be minimized. The public layer may expose only technical references needed for verification, audit and reconstruction.

Allowed public fields

  • subject_label
  • operator_label, where applicable
  • entity_type
  • record_scope
  • verification_level
  • payload_sha256
  • evt_id, where applicable
  • opc_id, where applicable
  • timestamp
  • status

Forbidden public fields

  • tax code / fiscal code;
  • document number;
  • identity document number;
  • identity card / CIE number;
  • passport number;
  • driving license number;
  • identity documents or scans;
  • portrait image or biometric material;
  • private evidence;
  • personal data or personal payload.

6. Minimum technical requirements

Public proof minimization

Public records must use minimized labels and hash-oriented proof references. Private verification evidence must remain outside the public layer.

Append-only registry

Public registry history should be extended through new entries, status updates or proof references, not silently rewritten.

Fail-closed verification

Missing, malformed, ambiguous, inconsistent or forbidden data must not produce validity.

  • MUST: no public tax-code custody.
  • MUST: no public document-number custody.
  • MUST: no public identity-document custody.
  • MUST: exact hash match for deterministic verification.
  • MUST: audit-first and fail-closed behavior.
  • MUST: clear distinction between IPR Base, IPR Verified and IPR Professional.

7. Creation / issuance boundary

IPR creation may produce technical records, controlled release objects and minimized proof references. IPR Base can be created as an R&D technical record.

IPR Verified requires a separate private verification process. The private evidence package must remain outside the public layer. Only minimized proof references may be published.

IPR Base

Technical R&D record. No verified identity claim.

IPR Verified

Private verification profile. Public proof remains minimized.

Registry Entry

Public label + verification level + hash + timestamp + status.

8. Verification

Verification is deterministic. A public proof reference is present only if:

  • the hash format is valid;
  • the public registry source is operational;
  • the proof reference is present;
  • forbidden public fields are absent;
  • the verification level is accepted.

Otherwise the result must be INVALID, NO_PUBLIC_RECORD or NON_OPERATIONAL. 

PUBLIC_REFERENCE_PRESENT
→ public proof reference exists only

NO_PUBLIC_RECORD
→ no matching public proof reference

INVALID
→ malformed, forbidden or rejected input

NON_OPERATIONAL
→ registry or verifier state invalid
