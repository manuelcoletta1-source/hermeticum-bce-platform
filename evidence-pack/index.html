Evidence Pack

An Evidence Pack is a technical proof package used to make an IPR-linked workflow verifiable, reconstructible and audit-ready. It can contain manifests, receipts, chain entries, EVT references, OPC references and hash-oriented proof material.

Evidence Pack is not a public container for private identity evidence. Tax codes, document numbers, identity documents, scans, portrait images, biometric material, private evidence and customer data must remain outside the public layer.

Policy: EU-first · audit-first · hash-oriented · fail-closed · append-only · no public identity custody

1. What an Evidence Pack is

An Evidence Pack is a structured technical package that allows a verifier, reviewer or auditor to reconstruct the proof path of an IPR-linked workflow.

It is designed for technical verification and audit support. It does not create legal certification, eIDAS qualification, regulated KYC / AML compliance, public authority validation or production authorization by itself.

3. Standard technical contents

Core files

  • PACK_MANIFEST.json — index of the package and expected hashes.
  • RESULT.json — technical result or report object.
  • CHAIN_ENTRY.json — append-only continuity entry.
  • receipt.json — optional technical receipt, where applicable.
  • FREEZE.md — optional append-only freeze declaration.

Proof references

  • payload_sha256 — hash-oriented commitment.
  • entry_hash — computed package entry hash.
  • evt_id — event continuity reference, where applicable.
  • opc_id — operational proof reference, where applicable.
  • verification_level — public scope label.

4. Supported verification levels

Evidence Pack may support the following public verification-level labels:

  • IPR_BASE_NOT_VERIFIED — technical R&D record, not verified identity.
  • IPR_VERIFIED_PRIVATE_CHECK — public proof reference connected to a private verification workflow.
  • IPR_PROFESSIONAL_PILOT — business / audit pilot profile based on IPR Verified.
  • RND_ONLY — R&D reference only.
  • NOT_APPLICABLE — verification level does not apply to the specific record.

These labels are technical scope indicators. They do not create legal identity, regulated KYC / AML compliance, eIDAS qualification, public authority approval or production authorization by themselves.

5. PACK_MANIFEST.json role

PACK_MANIFEST.json is the index of the package. It lists the expected files and their hashes. If a file changes, the hash changes. If the hash does not match, verification fails. 

PACK_MANIFEST
→ expected file list
→ expected hash list
→ verification level
→ EVT / OPC references
→ no private identity evidence
→ fail-closed verification

6. Freeze and append-only rule

A freeze declares that a package is crystallized. The package is not modified in place. If a new version is required, a new package or new chain entry should be created.

In-place modification breaks verifiability.

  • new evidence → new entry;
  • new version → new hash;
  • new correction → explicit superseding record;
  • silent rewrite → invalid audit posture.

7. Fail-closed rule

  • missing manifest → INVALID;
  • invalid JSON → INVALID;
  • hash mismatch → INVALID;
  • signature not verifiable → INVALID;
  • forbidden identity field → INVALID;
  • tax code in public artifact → INVALID;
  • identity document in public artifact → INVALID;
  • indeterminate field → INVALID.

8. Public proof interpretation

An Evidence Pack is a reproducible technical proof package. It can support audit review, verification and reconstruction.

It does not automatically create:

  • legal certification;
  • legal identity verification;
  • regulated KYC / AML compliance;
  • eIDAS qualification;
  • qualified trust-service status;
  • public authority validation;
  • external audit certification;
  • production compliance.
