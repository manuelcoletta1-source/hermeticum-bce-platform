Product: Critical Action Evidence Layer for AI-Assisted Enterprise Operations  
Status: Internal R&D / pilot-candidate commercial packaging  
Scope: B2B only

## 1. Purpose

This document defines the Level 1 commercial packaging used to qualify B2B pilot conversations for HBCE.

The pricing bands are launch-level qualification bands, not binding quotations. Final pricing depends on integration scope, customer environment, event volume, security review, data handling, support level and contractual risk allocation.

This document is not a public-sector procurement offer, not a defence offer, not a regulatory compliance certification, not a legal opinion and not a production service-level agreement.

## 2. Approved External Pricing Statement

HBCE B2B pilot pricing starts at EUR 150,000 for a controlled 90-day technical validation and at EUR 250,000 for bank-grade, cybersecurity-critical or regulated environments.

Final pricing depends on scope, integration, evidence requirements, security review, support level and contractual risk allocation.

| Offer | Indicative price | Duration | Primary deliverables |

| Annual Enterprise License after pilot | EUR 500,000 - 2,500,000/year | 12 months | Production-oriented license for agreed modules, environments, support, verification package, evidence export and change-control cadence. |

## 4. Minimum Commercial Floor

The minimum serious B2B entry point for a controlled technical pilot is EUR 150,000.

For bank-grade, cybersecurity-critical or regulated environments, the minimum serious entry point is EUR 250,000.

Below these levels, the engagement should be treated as advisory discovery, public documentation review, short written feedback or an introductory conversation, not as a custom pilot.

## 5. Commercial Rules

| Rule | Policy |
| --- | --- |
| Minimum pilot floor | EUR 150,000 for a controlled 90-day technical validation. |
| Regulated / bank / cybersecurity floor | EUR 250,000 minimum due to review, evidence, risk and integration overhead. |
| No free custom pilots | Unpaid custom work is limited to short written feedback, public documentation review or introductory calls. |
| No unclear scope | Any pilot must define target systems, demo workflows, evidence objects, acceptance tests, out-of-scope items and customer responsibilities. |
| No compliance guarantee | Pricing covers technical evidence production and validation support; it does not sell regulatory certification, court-proof liability attribution or legal compliance by itself. |

## 6. Qualification Gate

A prospect qualifies for a paid pilot only if it satisfies all required qualification conditions.

| Qualification question | Required answer for pilot |
| --- | --- |
| Does the organization run AI agents, automations, privileged actions or critical workflows? | Yes, with identifiable action classes. |
| Can it identify who owns the risk? | Named function such as CISO, CTO, AI Governance, Risk, Compliance, Platform Engineering or Audit. |
| Can it provide a controlled demo environment or mock equivalent? | Yes, without requiring classified or prohibited access. |
| Does it need evidence export, audit reconstruction or authorization traceability? | Yes, tied to a concrete use case. |
| Is there a budget path? | Discovery budget or pilot budget owner identified. |

Interest without owner, environment or budget is research feedback, not pipeline.

## 7. Packaging by Buyer Type

| Buyer type | Best initial package | Reason |
| --- | --- | --- |
| AI company / AI lab | 90-day AI Agent Tool Access Evidence Pilot | Fastest fit: tool calls, human authorization, scope, target receipt and verifier evidence. |
| Bank / fintech / insurance | Bank / Regulated Critical Action Evidence Pilot | Higher review burden: ICT risk, audit, privileged action, dual control and incident reconstruction. |
| Cybersecurity / SOC vendor | Critical Action Evidence Pilot | Security automation needs authorization traceability and clear post-action evidence. |
| Enterprise / multinational | Technical Discovery followed by 90-day Pilot | Best for mapping insider risk, platform actions, contractor authority and cross-system evidence. |
| Civil robotics / industrial automation | Discovery plus simulation or lab command-to-effect pilot | Requires safe non-defence framing, target receipt design and effect-observation boundaries. |

## 8. Included and Excluded

| Included in pilot pricing | Excluded unless separately contracted |
| --- | --- |
| Controlled HBCE runtime for agreed workflows. | Production deployment across the customer enterprise. |
| Schema and evidence object configuration for pilot scope. | Customer IAM, SIEM, GRC, cloud or robot vendor integration beyond agreed adapters. |
| Verifier CLI and human-readable verification report. | Independent legal opinion, regulatory certification or external audit signature. |
| Sample PASS/FAIL evidence bundles and failure cases. | 24/7 managed service, SOC operations or incident response retainer. |

## 9. Prohibited Claims

The Level 1 launch pack must not claim that HBCE:

- guarantees compliance
- proves legal responsibility
- replaces audit
- certifies AI Act, DORA, GDPR or eIDAS compliance
- provides defence-grade capability
- provides classified capability
- provides direct B2G procurement readiness
- performs real-world dispatch inside demo adapters
- proves physical truth by receipt alone

## 10. Runtime Boundary

Pricing and qualification are commercial launch-pack documentation only.

Runtime modules, demo adapters, EvidenceBundle generation and verifier output must not compute prices, produce quotations, create procurement offers or imply commercial acceptance.

The runtime evidence chain remains technical: identity, authority, scope, policy, precommit, receipt, bundle and verification.

## 11. Buyer-Facing One-Liner

HBCE Level 1 is a B2B Critical Action Evidence Layer for AI-assisted enterprise operations. It helps an organization record and verify who requested a critical action, under which authority and scope, which policy decision applied, what precommit was created, what target receipt was recorded, and how the evidence bundle verifies.
