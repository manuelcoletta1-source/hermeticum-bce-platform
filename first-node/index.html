  • Policy: UE-first · audit-first · fail-closed · hash-only · append-only

This declaration is structural: it defines the criteria for what counts as an operational node.

Minimum criteria (MUST)

Baseline compliance

Node MUST implement Baseline invariants: hash-only public layer, append-only trajectory, deterministic verification, fail-closed enforcement.

Deterministic verification

Node MUST support independent reproducibility: same input → same output (PASS/FAIL).

Append-only evidence

Node MUST publish only append-only proofs. Corrections are new entries, not edits of history.

Hash-only public posture

Node MUST avoid public personal data custody. Public surface stores cryptographic proofs only (GDPR-min posture).

Fail-closed behavior

Node MUST block execution when evidence is missing or inconsistent. No silent fallback.

Public entry points

Node MUST expose: verify interface, registry view, baseline reference, and standards reference.

Operational proof surface (this deployment)

This node exposes the required public surfaces:

  • /verify/ — deterministic verification (PASS/FAIL)
  • /registry/ — hash-only append-only public evidence
  • /baseline/ — versioned baseline (v1.0)
  • /standards/ — standard profiles
  • /status/ — operational status page

Baseline rule: if a decision cannot be reproduced independently, it is not admissible for execution.

What this enables

  • Third-party verification without platform trust
  • EU-grade accountability posture for AI and machines
  • Progressive federation: multiple nodes, same baseline
