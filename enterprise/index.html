1. Enterprise problem

Enterprise teams increasingly use AI to summarize, classify, compare and review documents. However, ordinary AI usage is often not sufficiently auditable.

A compliance, cybersecurity, legal operations or internal audit team may need to prove:

  • which document was analyzed;
  • which hash identifies the input;
  • which AI action was requested;
  • which operational identity or runtime was attached;
  • whether the record used IPR Base, IPR Verified or IPR Professional;
  • which governance decision was applied;
  • whether human validation occurred;
  • which EVT and OPC records were generated;
  • whether a final audit-ready report exists.

IPR AI Audit Trail addresses this gap by turning AI document work into an audit-ready technical trace.

2. Enterprise product hierarchy

IPR BASE

Technical R&D record

IPR Base is used for technical tests, proof flows, internal demonstrations and controlled R&D workflows. It does not create verified identity status.

IPR VERIFIED

Private verification profile

IPR Verified may use tax-code and valid identity-document evidence only inside a controlled private verification layer. The public layer stores only minimized proof references.

IPR PROFESSIONAL

Business / audit profile

IPR Professional is a future enterprise profile based on IPR Verified, intended for B2B pilots, AI governance workflows and audit-ready evidence chains.

The MVP is deliberately narrow. It proves one concrete workflow before moving toward broader productization.

6. IPR Verified boundary

For enterprise pilots, IPR Verified can be used as a private identity-verification profile when the pilot requires a stronger operational identity posture.

IPR Verified may use tax-code and valid identity-document evidence only in a controlled private layer. Accepted document categories are identity card / CIE, passport and driving license.

The public layer must not store tax codes, document numbers, identity documents, identity scans, biometric material, private evidence, personal data or customer payloads.

7. 30-day pilot model

A possible external B2B pilot should remain small and testable:

  • duration: 30 days;
  • users: 1–3 authorized operators;
  • IPR profile: IPR Base, IPR Verified or IPR Professional depending on scope;
  • documents: 10–20 synthetic, public or expressly authorized documents;
  • workflow: one AI-assisted document analysis process;
  • output: audit-ready report package;
  • review: usability, traceability, report clarity, validation workflow and governance value.

Any pilot involving confidential, personal, regulated, client or sensitive operational data requires prior legal, privacy and security review.

8. What the MVP is not

Operational statement

The current B2B value proposition is simple: AI-assisted document work can become IPR-linked, traceable, attributable, human-validated and audit-reportable.

IPR Verified strengthens the professional positioning of the gateway through private verification, while the public layer remains minimized, hash-oriented, non-custodial and non-certifying.
