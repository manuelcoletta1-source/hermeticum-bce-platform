Enterprise problem

Enterprise teams increasingly use AI to summarize, classify, compare and review documents. However, ordinary AI usage is often not sufficiently reconstructible for compliance, cybersecurity, legal operations, internal audit or governance review.

A responsible team may need to reconstruct:

  • which subject or operator used the workflow;
  • which IPR profile applied;
  • whether an IPR Card or access state was involved;
  • which document was analyzed;
  • which hash identifies the input;
  • which AI action was requested;
  • which governance decision was applied;
  • whether human validation occurred;
  • which EVT and OPC references were generated;
  • whether a final audit-ready report exists.

IPR AI Audit Trail addresses this gap by turning AI document work into an IPR-linked technical trace.

Enterprise product hierarchy

IPR BASE

Technical R&D record

IPR Base is used for technical tests, proof flows, internal demonstrations and controlled R&D workflows. It does not create verified identity status.

IPR VERIFIED

Private verification profile

IPR Verified may use identity evidence and national identifier evidence only inside a controlled private verification layer. The public layer stores only minimized proof references.

IPR CARD

Operational access key

IPR Card represents operational identity state, verification level, activation EVT, OPC receipt and public proof reference. It is not a state identity document or banking card.

IPR AI AUDIT TRAIL

First enterprise MVP

IPR AI Audit Trail is the first enterprise-friendly MVP use case: AI-assisted document analysis with IPR reference, document hash, human validation, EVT, OPC and report output.

JOKER-C2

Governed runtime boundary

JOKER-C2 is the AI Operational Runtime demonstrator. Enterprise access must be scoped through IPR state, policy, risk, security and pilot boundary.

HBCE

Governance ecosystem

HBCE connects identity, access, governance, registry, verification, EVT, OPC, audit continuity and fail-closed rules.

IPR VERIFIED AND IPR CARD BOUNDARY

Verified enterprise access requires private scope.

For enterprise pilots, IPR Verified and IPR Card can be used when the pilot requires a stronger operational identity posture. Identity verification, document review and national identifier checks belong only in a controlled private layer.

The public layer must not store tax codes, national identifiers, document numbers, identity documents, identity scans, biometric material, private evidence, personal data or customer payloads.

30-DAY PILOT MODEL

Small, bounded and reviewable

A possible external B2B pilot should remain small and testable:

  • duration: 30 days;
  • users: 1–3 authorized operators;
  • subject mapping: natural person, operator, team or organization;
  • IPR profile: IPR Base, IPR Verified or IPR Professional depending on scope;
  • IPR Card scope: included only where verification and access-state review are in scope;
  • documents: 10–20 synthetic, public or expressly authorized documents;
  • workflow: one AI-assisted document analysis process;
  • output: audit-ready report package;
  • review: usability, traceability, report clarity, validation workflow and governance value;
  • runtime: JOKER-C2 boundary only where separately scoped.

Any pilot involving confidential, personal, regulated, client or sensitive operational data requires prior legal, privacy and security review.
