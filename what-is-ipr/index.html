What is IPR?

IPR — Identity Primary Record is an operational identity and proof record. It connects an actor, a role, a digital event, a proof reference, a responsibility boundary and a continuity trace.

A login says who entered a system. A log says that something happened. A hash says whether data changed. A signature says who signed. IPR connects these elements into one operational frame: who or what acted, under which role, on which event, with which proof, with which responsibility and with which continuity.

IPR is the first operational product of the HERMETICUM B.C.E. research line and the base product inside the HBCE ecosystem. The first MVP built from it is IPR AI Audit Trail.

IPR is not a login, not a public identity document, not an IBAN, not a tax code and not a legal certification authority. It is an R&D/MVP operational identity and proof record with private verification and public proof minimization.

1. Simple definition

IPR is a stable reference for identity-linked digital operations. In ordinary systems, identity, access, logs, hashes, signatures and responsibility are often separated. IPR is designed to connect them into a single operational record that can be reviewed later.

The practical idea is simple: if a person, organization, AI system, node, document workflow or process performs an important operation, IPR gives that operation an identity-linked proof structure. This makes the operation attributable, reconstructable and verifiable. 

IPR =
identity reference

The purpose is technical and operational: make digital events attributable and verifiable without publishing private identity material in the public evidence layer.

2. The strongest analogy

IPR can be explained through a functional analogy, but it must not be confused with existing legal or financial identifiers. An IBAN organizes bank accounts inside the financial system. A tax code organizes subjects inside the administrative system. A digital signature validates an electronic act. A login allows access to a service.

IPR plays a comparable ordering role inside a governed digital ecosystem: it identifies an operational subject and connects that subject to actions, events, proof, responsibility and continuity. 

IBAN → account reference inside the financial system
Tax code → subject reference inside the administrative system
Digital signature → signature reference for an electronic act
Login → access reference for a service
Hash → integrity reference for data
IPR → operational identity and proof reference inside HBCE

IPR does not claim the legal status of a tax code, the banking function of an IBAN, the official status of an identity document or the regulated effect of a qualified digital signature. The analogy is functional: complex systems need stable reference instruments to organize identity, operations and responsibility.

3. Private verification model

IPR separates private identity verification from public proof. This is the core privacy and compliance posture. Identity evidence may be used privately to create or verify the IPR, while the public layer remains minimized.

5. What IPR is not

IPR must be understood precisely. It is not a social profile, not a password system, not a login account, not a wallet, not a public database of citizens and not a replacement for existing legal identity schemes. It is also not only a hash and not only a log, because a hash can prove that data has not changed, while a log can show that something happened, but neither one alone creates a complete operational identity model.

NOT A LOGIN
Access is not identity continuity
A login lets a user enter a system. IPR is designed to preserve an operational identity reference across events, proofs and audit reconstruction.
NOT A PUBLIC ID DATABASE
Verification is private, proof is minimized
IPR may use identity evidence privately, but the public layer must not become a database of identity documents, tax codes, document numbers or personal payloads.
NOT ONLY A HASH
Integrity is not attribution
A hash proves that a payload corresponds to a digest. IPR connects that proof to an operational identity and to a verifiable event chain.
NOT ONLY A LOG
Logging is not governance
A log records activity. IPR is designed to make activity reconstructable through identity, responsibility, evidence and verification rules.

IPR is best understood as an operational identity and proof layer for verifiable digital execution.

6. Why IPR matters

Modern digital workflows increasingly depend on AI assistance, automated processing, distributed teams, external providers, cloud environments and multi-step evidence chains. In these environments, it is not enough to know that a file exists or that a system produced an output. It becomes necessary to reconstruct which operational identity was involved, which event occurred, which evidence was generated, which checks were applied and whether the event can still be verified later.

This is the practical role of IPR. It gives HBCE a base product through which identity, event and proof can be treated as one verifiable operational unit. MATRIX remains the broader architectural framework, HBCE is the ecosystem that governs the workflow, and JOKER-C2 is the runtime demonstrator that shows how IPR can operate inside an AI-assisted environment.

7. Public evidence and private custody

IPR follows a privacy-minimizing model. The private identity or release file remains under private custody, while the public or shared evidence layer can store only proofs, digests, timestamps, receipts or registry references. This makes it possible to verify a record without turning the public layer into a database of personal identity payloads.

  • Private verification layer: may use tax-code and valid identity-document evidence.
  • Private evidence layer: keeps the full identity or operational release file under controlled custody.
  • Public evidence layer: stores hash-oriented proof, timestamps, receipts or registry entries.
  • Verification layer: checks whether the private file and public proof match.
  • Governance layer: defines whether a missing, broken or inconsistent proof must fail closed.

In the current MVP posture, IPR is a technical R&D mechanism with a target private verification model. It does not claim to be an official regulated identity scheme or a public authority registry.

9. Basic IPR flow

A simple IPR workflow begins with private verification or technical creation, continues with evidence generation and ends with verification. In practical terms, the system prepares an operational record, generates proof material, stores or references minimized evidence and allows a later verifier to check whether the record still matches the evidence.

STEP 1
Create the IPR record
Generate or prepare the operational identity record. For verified human IPRs, private tax-code and valid-document evidence belongs only in the private verification layer.

STEP 2
Generate evidence
Produce hash-oriented proof, event references, receipts or evidence-pack material connected to the record.
Evidence pack
STEP 3
Verify the record
Compare the available file, digest or proof material against the stored evidence and return a clear verification status.
Verify

The operational principle is simple: if the evidence is missing, inconsistent or unverifiable, the system should not present the record as valid.
