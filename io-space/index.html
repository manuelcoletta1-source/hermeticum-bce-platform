Enforcement / Non-compliance

ENFORCEMENT

OCE applica regole deterministiche. Non interpreta. Non “compensa”.

  • Canonicalization obbligatoria
  • Hash deterministico obbligatorio
  • Proof-only in pubblico (hash-only)
  • Append-only: niente riscritture
NON-COMPLIANCE

Se fallisci un requisito, l’evento non è opponibile. Punto.

  • Manifest ambiguo → INVALID
  • Hash non matcha → INVALID
  • Fonte non leggibile → FAIL-CLOSED
  • Dati sensibili in pubblico → BLOCK
AUDIT

La prova resta. L’audit resta. La storia resta. È così che si scala la responsabilità.

  • Ricostruibilità nel tempo
  • Non ripudio (proof)
  • Minimizzazione pubblica

Modello (deterministico)

1) Manifest canonico

Definisce l’evento in forma strutturata e normalizzata. Ambiguità = invalidità.

2) event_hash

Hash deterministico calcolato dal manifest canonico. Stesso input → stesso output.

3) Proof pubblica

Pubblico = hash-only + timestamp (+ metadati non sensibili). Fine.

Regola

Un evento è opponibile solo se un terzo può riprodurre il match deterministico. Se non può → non è opponibile. Se la fonte non è leggibile → fail-closed.
