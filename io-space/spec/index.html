IO-SPACE (OCE) — Specifica Operativa

Questa pagina definisce la SPEC ufficiale di IO-SPACE come Operational Certification Engine (OCE). Il modello è deterministico: manifest canonico → event_hash → proof. Se un requisito fallisce → FAIL-CLOSED.

Definizioni

Manifest (canonico)

Rappresentazione strutturata dell’evento dopo canonicalization. Ambiguità o indeterminismo → INVALID.

event_hash (deterministico)

Hash calcolato dal manifest canonico con regole deterministiche. Stesso input → stesso output. Se differisce → l’evento è alterato.

Proof (pubblica)

Pubblico = hash-only + timestamp (+ metadati non sensibili). La prova pubblica non contiene dati personali.

Policy operative (vincoli)

  • UE-FIRST: baseline normativa e operativa UE.
  • AUDIT-FIRST: priorità alla ricostruibilità e verificabilità.
  • HASH-ONLY: in pubblico solo prove minimizzate.
  • APPEND-ONLY: nessuna riscrittura del ledger pubblico.
  • FAIL-CLOSED: in caso di dubbio o fonte non verificabile → blocco.
  • GDPR-MIN: minimizzazione; nessuna custodia pubblica di dati personali.

Requisiti minimi (input)

Identità

L’evento deve essere riferibile a un contesto di identità operativa (IPR). Se l’identità non è validabile → BLOCK.

Canonicalization

Regole per normalizzare e rendere l’evento deterministico. Se la canonicalization non è definita → INVALID.

Proof-only publication

Qualunque uscita pubblica deve essere minimizzata (hash-only). Se emergono dati sensibili in pubblico → BLOCK.

Enforcement Matrix (esiti obbligatori)

Questa matrice definisce cosa succede quando una condizione fallisce. Non esistono “mezzi stati”. L’esito è deterministico.

VALID
  • Fonte leggibile
  • Manifest canonico
  • event_hash riproducibile
  • Pubblico hash-only
INVALID
  • Hash non matcha
  • Manifest ambiguo/indeterministico
  • Canonicalization mancante
  • Incoerenza strutturale
BLOCK / FAIL-CLOSED
  • Fonte non leggibile/non disponibile
  • Violazione minimizzazione (dati sensibili pubblici)
  • Identità non validabile
  • Policy breach

Output (pubblico vs privato)

Pubblico (ledger)

Pubblica solo prove minimizzate: hash + timestamp (+ metadati non sensibili).

Privato (operativo)

Dettagli operativi restano fuori dal registro pubblico. Il pubblico deve poter verificare la prova senza accedere ai dettagli.

Audit (ricostruzione)

Un terzo deve poter riprodurre determinismo e match, a parità di input canonico.
