VERIFY · IPR CARD · REGISTRY · EVT · OPC · PUBLIC HASH REFERENCE · FAIL-CLOSED

Verify public proof references, not private identity evidence.

Verify is the HBCE public proof reference gateway for IPR records, IPR Card references, activation EVT records, OPC receipts and hash-oriented registry evidence.

In the new Platform architecture, verification sits after the operational chain: IPR Onboarding App → IPR Card → public proof → Registry → Verify. This page checks technical proof references. It does not verify identity documents, tax codes, national identifiers, selfies, liveness videos or private evidence packages. Those belong to the private verification layer and must not be inserted into public verification fields.

A public match means that a minimized public proof reference exists. It does not prove official identity, legal validity, regulated KYC / AML compliance, eIDAS qualification, public authority validation, cybersecurity assurance, production authorization or JOKER-C2 access by itself.

PUBLIC VERIFICATION STATES

PUBLIC_REFERENCE_PRESENT means that a matching public proof reference exists. NO_PUBLIC_RECORD means that no matching public proof record was found. INVALID means that the input is missing, malformed, forbidden or rejected. NON_OPERATIONAL means that the registry or verifier source is unavailable, malformed or inconsistent.

WHAT VERIFY CHECKS

Verify checks minimized proof references.

The verifier can compare local text against an expected SHA-256 value or check whether a payload_sha256 reference exists in the public HBCE registry index. This makes it useful for IPR records, IPR Card public references, activation EVT payloads, OPC receipts, evidence packs and IPR AI Audit Trail reports.

REGISTRY VERIFY

Public registry reference verification

This surface checks whether a payload_sha256 commitment is present in the HBCE public registry index. The source is registry/registry.json and it must satisfy registry v3 fail-closed rules, public-data minimization rules and accepted verification-level values.

INPUT

payload_sha256 or public JSON object

Insert a 64-character SHA-256 value, or paste a public JSON object containing payload_sha256. If the JSON does not contain payload_sha256, the verifier computes a local SHA-256 commitment from the JSON after removing common hash-output fields.

Do not paste private identity evidence, tax codes, national identifiers, document numbers, credentials, private keys, selfies, videos or client payloads.

RESULT

Public reference state

Missing match returns NO_PUBLIC_RECORD. Invalid registry state returns NON_OPERATIONAL. Ambiguous, malformed or forbidden public input returns INVALID.

TECHNICAL VERIFY

Technical deterministic verification

Paste public or controlled local content exactly as stored and compare it against the expected SHA-256 value. This tool hashes the exact UTF-8 text inserted by the user. No normalization is applied.

INPUT 01

Local text

Paste the full local text to hash. This may be an IPR public reference, IPR Card public object, EVT payload, OPC receipt, evidence-pack manifest, registry record or controlled proof artifact. Do not paste private identity documents, tax codes, national identifiers, secrets, credentials or private evidence.

INPUT 02

Expected proof hash

Paste the expected SHA-256 from a public registry entry, evidence-pack reference, OPC receipt or controlled proof record.

Lowercase hex only. Invalid format returns fail-closed.

Missing means failure

Missing text, invalid hash format, invalid registry state, no public match, forbidden identity fields or mismatch never produce implicit validity.
