Why fail-closed

  • No unverifiable execution
  • No partial validity
  • No trust required: only proofs
  • Invalid by default if a proof cannot be reproduced

If a verifier cannot reproduce the status deterministically, the safe default is BLOCK.

Failure reasons (what breaks verification)

Reason Meaning Fix
Invalid JSON Proof cannot be parsed deterministically. Provide valid JSON (Release/Certificate).
Hash invalid format Expected hash is not 64-hex (lowercase). Paste the correct payload_sha256.
Expected mismatch Computed hash does not match the expected hash. Use the correct proof file or the correct expected hash.
Not in registry Hash-only entry was not appended (append-only). Request operator append; then verify again.
Registry unreachable Public proof cannot be fetched. Check connectivity / deployment / path.
