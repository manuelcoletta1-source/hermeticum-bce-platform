Verify IPR status

Verification is deterministic: it proves Release integrity and registry presence. The outcome is binary: VALID or INVALID. If verification cannot prove identity → BLOCK (fail-closed).

Rule: VALID IPR = FILE INTEGRITY OK + PRESENT IN REGISTRY.

Verification inputs

VERIFY needs two data sources: a private proof (Release) and a public proof (registry). Public proof is hash-only (GDPR-min).

Private input
IPR Release file (customer custody)
Public input
Registry entry (label + payload_sha256 + timestamp)
Output
VALID / INVALID (fail-closed)
This page explains the rule and failure modes. Actual file handling can be added client-side when needed.
If the hash is missing or not 64-hex → invalid by definition.

Why it is fail-closed

  • No unverifiable execution
  • No partial validity
  • No trust required: only proofs

If a verifier cannot reproduce the status deterministically, the safe default is BLOCK.

Deterministic outputs

VALID IPR
VALID
  • Release integrity OK
  • payload_sha256 computed deterministically
  • Registry match found (append-only)
Access granted to modules, catalogue tiers, and operator paths (if licensed).
INVALID IPR
INVALID
  • Release integrity cannot be proven, or file missing
  • payload_sha256 invalid format / not reproducible
  • Registry match not found
  • Verification cannot run deterministically
Access blocked by design (fail-closed).
Audit clarity: every INVALID case is explainable as a missing proof, a broken integrity condition, or absent registry match.

Failure reasons (what breaks verification)

Reason Meaning Fix
Missing Release No private proof → integrity cannot be proven. Recover Release from secure storage (or re-issue).
Hash mismatch The computed fingerprint does not match the expected hash. Use the correct Release file and compare with the right entry.
Not in registry Hash-only entry was not appended (append-only). Request operator append; then verify again.
Non-deterministic verify Verification cannot be reproduced. Fix tooling and ensure deterministic calculation paths.
