Public proof verification gateway

Verify is the public proof verification gateway of the HBCE system. It exposes two complementary surfaces:

Registry verification checks whether a payload_sha256 commitment is present in the public registry.
Technical verification computes SHA-256 over local text and compares it with an expected hash.

Missing, invalid, malformed, ambiguous, or non-reproducible states are treated as failure by design.

PUBLIC VERIFICATION LIMIT

A public registry match means that a public proof commitment is present. It does not replace private evidence review, identity verification, contractual qualification, legal authorization, or institutional validation.

Registry public proof verification

This surface checks whether a payload_sha256 commitment is present in the HBCE public registry. The verification source is registry/registry.json and must satisfy the registry v3 fail-closed schema.

INPUT

payload_sha256 or JSON object

Insert a 64-character lowercase SHA-256 value, or paste a JSON object containing payload_sha256. If the JSON does not contain payload_sha256, the verifier computes a local SHA-256 commitment from the JSON after removing common hash-output fields.

RESULT

Public proof state

Missing match returns NO_PUBLIC_RECORD. Invalid registry state returns NON_OPERATIONAL.

Position in the system

Verification is not a standalone utility. It is the reconstruction layer of the HBCE system: registry exposes public proof commitments, while verification reproduces deterministic comparison or public proof lookup.

Technical deterministic verification

Paste local content exactly as stored and compare it against the expected SHA-256 value. This tool hashes the exact UTF-8 text inserted by the user. No normalization is applied.

INPUT 01

Local text

Paste the full local text to hash. This may be a local release object, manifest, receipt, or controlled proof artifact.
